# Audio (Speech, Transcription, Audio Input) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `POST /v1/audio/speech` and `POST /v1/audio/transcriptions` through the router for Gemini, OpenRouter and stepfun, convert speech to the client's format (Ogg Opus for annai) with `ffmpeg`, and let Gemini chat models take `input_audio`.

**Architecture:**
- **provider:** gains two operations, `OpSpeech` and `OpTranscribe`. Each dialect gets a builder and a reader:
  - OpenAI-kind passes through;
  - stepfun-flavored OpenAI-kind translates transcription to its SSE route;
  - Gemini is translated to `generateContent`.
- **router:** gains `ExecuteSpeech` and `ExecuteTranscription`. They reuse `run` / `judge` / `settle`, applying per-target speech settings and the audio time limit.
- **server:** owns the two routes. It parses both transcription request shapes, converts speech with the new `audioconv` package, renders replies, and logs audio as size and type only.

**Tech Stack:** Go 1.26 standard library plus `github.com/BurntSushi/toml`; `ffmpeg` via `os/exec`; tests with `net/http/httptest`.

**Spec:** `docs/superpowers/specs/2026-10-19-audio-design.md`. "D*n*" means the spec's decision *n*.

## Global Constraints

- Go 1.26; standard library plus `github.com/BurntSushi/toml` only. `ffmpeg` only through `os/exec`.
- **Unchanged:** chat, embeddings and Responses behavior, except Gemini receiving `input_audio` and logged bodies leaving out audio (D20). Every existing test passes unchanged.
- **Speech formats** are exactly `opus`, `mp3`, `aac`, `flac`, `wav`, `pcm`. The default for the client is `mp3` (D14).
- **`pcm`** is 24 kHz, mono, 16-bit signed little-endian (D15). When asking stepfun for `pcm`, also send `sample_rate: 24000`.
- **What OpenAI-kind targets are asked for:** the target's configured `format`, else `pcm` (D21). Gemini always returns WAV or L16.
- **Encodings** (D16), output `ffmpeg` arguments and `Content-Type`:
  - `opus`: `-c:a libopus -b:a 32k -ac 1 -application voip -f ogg` → `audio/ogg`
  - `mp3`: `-c:a libmp3lame -b:a 64k -ac 1 -f mp3` → `audio/mpeg`
  - `aac`: `-c:a aac -b:a 48k -ac 1 -f adts` → `audio/aac`
  - `flac`: `-c:a flac -f flac` → `audio/flac`
  - `wav`: `-c:a pcm_s16le -f wav` → `audio/wav`
  - `pcm`: `-f s16le -ar 24000 -ac 1` → `audio/pcm`
- **Voices:** a target's configured voice beats the client's (D13). On Gemini, an unknown or empty voice becomes `Kore` (D22). Gemini's 30 voices are Zephyr, Puck, Charon, Kore, Fenrir, Leda, Orus, Aoede, Callirrhoe, Autonoe, Enceladus, Iapetus, Umbriel, Algieba, Despina, Erinome, Algenib, Rasalgethi, Laomedeia, Achernar, Alnilam, Schedar, Gacrux, Pulcherrima, Achird, Zubenelgenubi, Vindemiatrix, Sadachbia, Sadaltager, Sulafat.
- **`ffmpeg` missing, failing or silent** (D10): send the provider's audio as it came, with its true type. Raw PCM / L16 is first wrapped in a WAV header in Go. Never fail the request for this.
- **Logs** (D11, D20): audio becomes `"<N bytes <type>>"`, never bytes, in the audio routes' logs and in chat/Responses `input_audio` data. Attempts never store a downstream audio body.
- **Success** (D19):
  - speech: a 2xx with non-empty audio;
  - transcription: a 2xx with a `text` string, which may be empty;
  - anything else is `bad_output` (next key, no blackout).
- **Audio time limit:** each attempt is limited by `[server] audio_timeout` (default `10s`), taking the shorter of it and the provider's `timeout` (D23). Running out is a `provider_error` with blackout.
- **stepfun transcription `error` events** caused by the request itself count as HTTP 400: next target, no blackout. Others are provider errors (D24).
- **Anthropic targets** are incompatible for audio: skipped, nothing sent.
- **Tests needing `ffmpeg`** call `t.Skip` when `exec.LookPath("ffmpeg")` fails.

## Review Focus

1. **A speech `input` over a provider's limit** (stepfun's 1,000 characters) answers 400 on that target; the next target serves it, and nothing is blacked out. Test: Task 7, `TestSpeechFailsOverOn400WithoutBlackout`.
2. **A transcription upload with no file extension and `application/octet-stream`** falls back to format `wav`. Test: Task 8, `TestTranscriptionFormatFallsBackToWav`.
3. **A Gemini speech reply with no audio part** (a text reply, or a safety block) is never a 200 with an empty body: it's `bad_output` or `prohibited`, and the next target serves. Test: Task 5, `TestGeminiSpeechWithoutAudioIsNotContent`.
4. **A client that disconnects during conversion** stops `ffmpeg` promptly, with no leftover process. Test: Task 2, `TestConvertStopsWhenCanceled`.
5. **A transcription of silence** (empty `text`) is a success, not a failover that spends a paid fallback. Test: Task 7, `TestEmptyTranscriptIsSuccess`.


### Task 7: Routing audio

**Files:**
- Create: `router/audio.go`, `router/audio_test.go`
- Modify: `router/router.go` (`outputOK` for audio ops; `Result.ContentType`)

**Interfaces:**
- Consumes: Tasks 1, 5 and 6.

```go
func (r *Router) ExecuteSpeech(ctx context.Context, inboundModel string, req provider.SpeechRequest) *Result

// Result gains: ContentType string // speech: the audio's type as the provider sent it
```

**Behavior:**
- **Routing:** both go through `run` with a `tryFunc` that builds the `provider.Request`. It sets `AudioAPI` from `p.Audio`, `FFmpeg` from the config, and `Provider`.
- **Per-target speech settings:**
  - **Voice:** `st.cfg.Models[inboundModel].Speech["<provider>/<model>"].Voice`, else `req.Voice`.
  - **Format:** for OpenAI-kind targets, the configured `format` else `"pcm"`.
- **Each call** gets a context with timeout `min(AudioTimeout, p.Timeout)`. `judge` receives the inbound context, so a timeout is a provider error, not "canceled".
- **`outputOK`** for `OpSpeech` and `OpTranscribe` is `resp.HasContent`.
- **On success**, `Result` gets `Body`, `ContentType` and `Status`.
- **On exhaustion:**
  - when only incompatible targets were found, 400 `"no configured target for this model can serve audio"`;
  - otherwise today's `exhaustedHTTPStatus` rules.

### Task 8: The server routes, conversion, logs, and the README

**Files:**
- Create: `server/audio.go`, `server/audio_test.go`
- Modify: `server/server.go` (`Register`), `README.md`

**Interfaces:**
- Consumes: `router.ExecuteSpeech` / `ExecuteTranscription` (Task 7); `audioconv` (Task 2); `config.SpeechFormats`.
- Produces: handlers `handleSpeech` and `handleTranscription`, registered at `/v1/audio/speech` and `/v1/audio/transcriptions`.

**Behavior:**
- **Speech:**
  - **Request:** a JSON body. `model` and `input` are required (400 otherwise). `response_format` must be one of `SpeechFormats` (default `mp3`). `stream_format` is dropped, and every field not otherwise used goes into `Extra`.
  - **Success:** if `!audioconv.Matches(res.ContentType, format)`, convert with the config's `ffmpeg` and the request context. If that fails, wrap raw PCM in WAV, keep the original otherwise, and log `WARNING: speech not converted to <format>: <err>`.
  - **Reply:** 200 with the audio and its true `Content-Type`.
- **Transcription:**
  - **Request:** `multipart/form-data` (`ParseMultipartForm(32<<20)`) or JSON with `input_audio`.
  - **Format:** `input_audio.format`, else the file name extension, else the part's `audio/<x>` type, else `wav`.
  - **Reply:** `json` gives `{"text":…}` as `application/json`. `text` gives the text as `text/plain; charset=utf-8`. `verbose_json` gives the provider body (or `{"text":…}` from other targets).
- **Both:**
  - **Before routing:** auth, then the in-flight register. The preview is the start of `input` for speech, and `audio <KB> KB <format>` for transcription.
  - **Failure:** today's JSON error.
- **Log entries:**
  - **Request:** JSON of the fields, with audio as `"<N bytes audio/<format>>"`.
  - **Response:** `{"audio":"<N bytes <type>>"}` for speech, the JSON for transcription.
